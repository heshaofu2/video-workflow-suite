> **本阶段只做粗剪**：粗切 +（可选）去静音。不去口水词、不加字幕。

## 整体流程

```
Step 1: 核对视频、现有转写或已确认时间范围
Step 2: 选分割维度（先问用户：按咨询人 / 按话题 / 组合）→ 按维度出候选段
Step 3: 边界检查 + AI 验收 → clips.list
        ⏸ 选段清单必须先交用户确认，确认后才剪
Step 4: 粗剪执行（clip cut）
```

## 分割维度（选段第一步：必须先问用户）

切片前先确认**按哪个维度分割**——这是"用什么方式切"的核心选择，不要替用户默认：

- **维度 A · 按咨询人/对话人**：每位说话人或对话单元作为一条（访谈每位嘉宾、咨询每位提问者、辩论每方）。适合完整保留某人观点、按角色切。**依赖 speaker 标签**，缺少时引导用户用所选转写工具补充。
- **维度 B · 按话题**：每个话题/议题作为一条。适合知识点、观点传播、短视频。
- **组合**：先按对话人分大块，块内再按话题细分（多人多话题长视频常用）。

### 话题的形态属性（不是分割维度，是挂在话题上的标注）

按话题切时，给每个话题标注**适合做成哪种形态**，供挑话题时参考（不改变"按话题分割"这个维度本身）：

- **观点版（opinion）**：完整讲清一个观点（铺垫 → 观点 → 例子 → 收束 至少 3 项）
- **金句版（punchline）**：一句话的传播点，允许更短，但单句必须成立

同一话题可能两种形态都行；形态只是切的时候的呈现方式。

### 按话题分割时，每个话题候选必须给齐这些信息（供用户挑选）

不要只给一句标题就让用户选——每个候选话题都要列出下面这些，方便用户判断要不要：

| 字段 | 内容 |
|------|------|
| **话题** | 一句话标题 |
| **时长** | 时段（H:MM:SS–H:MM:SS）+ 总时长 |
| **信息总结** | 2–3 句概括这段在讲什么、核心观点是什么 |
| **关键金句** | 1–2 句最有传播力的原话引用 |
| **开头原文** | 切入点附近的原话（让用户判断从哪起） |
| **结尾原文** | 切出点附近的原话（让用户判断切到哪收） |
| **形态** | 建议观点版 / 金句版 |

## Step 1: 素材准备

1. 依照共享规则核对视频与产物目录，通常直接使用原文件路径。
2. 语义选段需要对应时间轴的转写；缺少时按 [转写材料契约](../../video-shared/references/transcript-contract.md) 说明格式和覆盖范围，引导用户通过其选择的工具取得。用户已明确时间范围且只要粗切时不强制生成转写或摘要。
3. 候选话题可复用 `insights.md`；本 Skill 对其核对上下文和实际切点，不重新生成一套完整观点报告。

## Step 2-3: 选段 + 边界检查 + AI 验收

**最关键的一步——不能凭直觉猜时间戳，必须先确定模式，再基于转写文字精确定位。**

### 候选来源
- 优先用 insights.md 的核心观点 / 金句 / 争议点
- 或人工给出主题，再用转写 JSON 定位

### 用转写校准边界

统一通过 `transcript read` 获取对应范围的完整转写段落：

```bash
"$VIDEO_CLI" transcript read --input "$OUTDIR/transcript.json" \
  --start 0:44:52 --end 0:49:26
```

返回的是相交的完整段，不代表逐字切点已经确定；继续按下方边界标准检查。

### 精确边界原则

**观点版**：
1. 观点完整：从铺垫 → 结论，不截断
2. 前不带冗余：切掉闲聊、过渡
3. 后不拖尾：观点讲完即切
4. 向前后各扩 2-3 分钟确认边界

**金句版**：
1. 单句必须成立
2. 前后最多保留少量必要上下文
3. "听起来像话说一半"则不合格

### 边界完整性检查（`clip boundary`，语义选段验收前执行）

直观查看切入/切出点的实际文字内容：

```bash
# 单条检查
"$VIDEO_CLI" clip boundary \
  --transcript transcript.json \
  --start 0:44:52 --end 0:49:06 \
  --mode opinion --suggest

# 批量检查整个 clips.list
"$VIDEO_CLI" clip boundary \
  --transcript transcript.json \
  --clips clips.list --suggest
```

脚本输出可视化逐段文字预览（`█` 切片内容 / `░` 上下文 / `✂️` 切入切出点）、自动检测的边界风险（反问未回答、同一人继续说、连词续接等），`--suggest` 会建议更安全的结束点。

**必查项**（看 `✂️ 切出点` 后面的 `░` 下文）：
- 下一句是不是当前论点的结论？→ 是则必须延伸
- 同一说话人紧接着继续说？→ 可能话没说完
- 下一句以"那/但是/所以"开头直接回应？→ 建议包含

### AI 验收（必须）

验收的核心问题：**这段能不能脱离原视频上下文，独立成为一个完整短视频？**

检查项：开头 3-5 秒能否听懂、是否有明确观点句、是否有解释/例子、**结尾是否收住**（最后一句是完整陈述句 / 多人对话含"挑战-回应"完整对 / 下一句不是当前论点的直接结论）。

验收输出格式：
```json
{
  "mode": "opinion",
  "start": "0:44:52",
  "end": "0:49:26",
  "title": "先想清楚产品再定形态",
  "why_passed": ["开头有场景铺垫", "中间有观点交锋", "结尾有明确落点"],
  "risks": ["前 3 秒钩子较弱"],
  "decision": "pass"
}
```
`decision != pass` 则回到候选阶段重选，不要硬切。

### ⏸ 用户确认（硬性 checkpoint）

选段清单（每条：**时间范围 · 时长 · 观点/主题 · 模式**）**必须交用户确认、调整、拍板**后，才进入 Step 4 粗剪。不要从选段一口气跑到剪辑。

> **批量处理多个视频时**：每个视频都要**独立重走一遍本流程**（选分割维度 → 出候选清单 → 用户确认），**不要沿用上一个视频的选择**（话题、条数、维度都可能不同）。用户说「其他视频也这样处理」指的是复用同一套**流程**，而不是复用具体的选段结果。

### 时间戳格式
- < 60 分钟：`MM:SS`（如 `41:40`）
- ≥ 60 分钟：`H:MM:SS`（如 `1:50:08`）

## Step 4: 粗剪执行（clip cut）

`clip cut` 做粗切 +（可选）去静音。**不含去口水词、不加字幕。**

```bash
# 单条
"$VIDEO_CLI" clip cut \
  --input video.mp4 \
  --start 30:16 --end 31:58 --name "01-胆子够大" \
  --output ./clips/

# 批量（clips.list 每行: 开始|结束|名称）
"$VIDEO_CLI" clip cut \
  --input video.mp4 \
  --clips clips.list \
  --output ./clips/

# 纯粗切（保留原貌，不去静音）：加 --no-desilence
"$VIDEO_CLI" clip cut \
  --input video.mp4 --clips clips.list --output ./clips/ --no-desilence
```

**去静音**：脚本默认开启——`silencedetect` 检测 ≥0.5s 静音 → 切出非静音段 → concat 拼接。加 `--no-desilence` 则纯粗切、完整保留原始停顿；本 Skill 在用户未要求去静音时使用这一模式。当前脚本未实现接点音频淡化，不能声称它已自动消除剪口杂音。

**产出**：每条 `<名称>.mp4`（粗剪成品，无字幕）。

> CLI 可处理单条或批量选段。输出重名会被拒绝，不通过重复启动同一输出任务来加速。

## 多段拼接（金句 hook + 正文段落）

从不连续时间段拼一条短视频：各段分别用 `clip cut` 粗剪，再用 `clip join` 按顺序拼接。

```bash
# 各段粗剪完成后，确认编码参数匹配，再按顺序拼接
"$VIDEO_CLI" clip join --input \
  "$OUTDIR/clips/00-hook-金句.mp4" \
  "$OUTDIR/clips/01-正文段落1.mp4" \
  "$OUTDIR/clips/02-正文段落2.mp4" \
  --output "$OUTDIR/FINAL.mp4"
```

## 命令清单

| 命令 | 用途 |
|------|------|
| `clip cut` | 粗剪（粗切 + 可选去静音，单条/批量，支持并行） |
| `clip boundary` | 选段边界完整性检查（逐段文字可视化 + 风险检测 + 端点建议） |

## 依赖

运行环境由共享层的 `doctor` 检查。语义选段需要同源转写 JSON，用户已确认时间范围的直接粗切不强制转写。

## 踩坑记录

| 问题 | 原因 | 解决 |
|------|------|------|
| 音画不同步 | select/aselect 滤镜音视频时间基不同 | 改用 trim/atrim + concat |
| 时间戳不认 | `109:30` 超过 59:59 | 改为 `H:MM:SS`（`1:49:30`）|
| macOS zsh 报错 | `mapfile` 不存在 | 用 `while IFS= read -r line` |
| 中文文件名乱码 | nohup 后台 + CJK 路径 | 建英文 symlink |
| 跳切"咔哒"声 | 拼接点音频突变 | 实际试听并调整剪点；当前脚本未自动处理接点淡化 |
| MM:SS 时间戳解析歧义 | `25:55` 在某些场景被错误解析 | clips.list 统一用 `H:MM:SS` |
| 结尾"话说一半" | 按时间戳切断，论点跨 segment | `clip boundary` 预检 + AI 验收结尾检查 |

## 性能参考

| 切片数 | 总原始时长 | 粗切+去静音耗时 |
|--------|-----------|----------------|
| 8 条 | ~15 min | ~2-3 min |
| 14 条 | ~35 min | ~5-6 min |

> 纯 ffmpeg 操作，很快。去静音会对每段重编码，略增耗时；`--no-desilence` 纯粗切最快。
