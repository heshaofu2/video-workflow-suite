## 按材料衔接，不绑定转写工具

剪辑、去重、观点提炼和字幕处理只约定输入材料，不依赖特定转写 Skill、模型、芯片或本机识别环境。现有文字稿、字幕和时间戳无论由何种工具生成，只要满足本次数据与时间要求即可复用。用户已给定剪辑范围时无需转写；纯文字分析无需为视频剪辑补时间戳。

先检查项目内已有文字、字幕、词级结果及其来源。只有当前步骤确实缺少材料时，才引导用户完成转写：

- 说明用途和所缺内容：语义选段或去重定位需要同源带时间文字稿，字幕处理需要最终剪辑时间轴的完整 SRT；精修剪口或字幕时按需补词级时间，按人选段时才补说话人标签。
- 沿用用户已有转写工具或服务；可由当前可用的独立转写能力完成，也可引导用户在熟悉的软件中导出。告知待转写的媒体路径、覆盖范围和所需产物，不要求安装 MLX、下载模型或更换设备。
- 用户未指定方式且需要选择时，给出当前实际可用的选项；例如：“为了定位重复句，需要这段视频的带时间文字稿。可以导入已有结果，或用你选择的转写工具生成；请保留每段的起止时间。”选择尚未确定时，继续不依赖该材料的检查，不猜测文字或时间。
- 接到结果后核对来源、覆盖范围与时间基准，再继续剪辑。格式不符时先说明差异；只转换已有数据，不伪造词级时间或说话人标签，不覆盖原文件。

相邻的 [video-to-text](../../video-to-text/SKILL.md) 可协助取得转写材料，其中 `transcript run / segments` 是可选的本地 MLX 实现。仅在用户选择且环境适用时使用；其环境缺失不阻断其他功能，也不触发自动安装或全片重转。

## 数据与时间要求

- 带时间的 JSON 至少含 `segments`，每段有非负、有限的 `start`、`end` 秒数与 `text`，结束不早于开始。说话人可放在 `speaker`。
- 词级时间按使用命令需要提供 `segments[].words[]` 或顶层 `word_segments`，每词含 `start`、`end` 与 `word`。有则复用，缺失时说明精度限制或引导补齐，不把两套字段或特定引擎元数据作为所有转写的门槛。来源、时间基准和实际媒体时长应在产物或随附记录中保留；内置分段合并要求每段 JSON 记录 `duration`。
- 保留源媒体路径和转写覆盖范围。原片时间、局部片段时间和剪后时间必须注明；将局部转写用于原片时加回提取区间偏移。
- `transcript read` 可读取 TXT 或 JSON。按时间筛选需要 JSON，返回与请求区间相交的完整段落，不是逐字剪裁后的文本，也不会证明该转写和某个视频已经匹配。
- 转写文字不等于实际声音。专名、音乐下的假词、零长度词和低置信度内容回到音频与画面核实，不据此改写实际说话内容。

## 复用与局部补充

只缺说话人标签时补标签；只需复核剪口时提取局部音频再转写，并记录提取起点与时间偏移。切片、去重、重排或去静音后，原片时间戳必须通过实际剪辑映射转换，或对最终成片补转写。

分段合并按各段记录的实际媒体 `duration` 累加偏移，同时移动段落和两种词级时间，不能按最后一句结束时间计算。分段编号必须从零连续；缺段或没有媒体时长的旧结果会被拒绝，需要核对媒体后补齐。合并后仍检查实际分段交界，不把识别时间当成已试听确认的切点。

## 字幕职责

转写输出的 SRT、ASS 是基础字幕。按意群和阅读长度重分段归 `subtitle-resegment`；字幕精修应保留完整文字并使用最终剪辑时间轴。具体分段规则只在字幕 Skill 维护，不在去重或转写流程中另写一份。
